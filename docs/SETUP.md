# 導入手順

Play ストアからアプリをインストールしたところがスタートです。
各自が自分の Google Cloud を契約し、そこにバックエンドと写真用バケットを作り、アプリをつなぎます。
**OAuth クライアントを登録するのは公開者だけで、利用者は登録しません。**

> **状態**: 目標設計に基づく手順です。バックエンド(`backend/`)と新しい Terraform は未実装のため、
> 5章のコマンド名・変数名・URL などは実装時に確定します。設計は `docs/BACKEND_DESIGN.md` を参照。

| 役割 | 誰か | 必要なもの |
| --- | --- | --- |
| 公開者 | アプリを Play で配布する人 | OAuth クライアント(1回だけ設定) |
| オーナー(管理者) | 自分の GCP を契約してバックエンドを持つ人 | Google アカウント、課金を有効にした GCP プロジェクト |
| メンバー | 招待されて参加する人 | Google アカウントのみ(GCP の契約は不要) |

1人のユーザーが持てる自分のバックエンドは1つだけです。他人のバックエンドのグループには、いくつでも参加できます。

費用は主に GCS の保存料金です。Cloud Run は最小インスタンス0で、個人利用ならほぼ無料枠に収まる見込みです。

---

## 1. 公開者の設定(1回だけ)

アプリを Play に載せる人が、次を設定します。オーナーやメンバーは行いません。

1. GCP プロジェクトを用意し、**OAuth 同意画面**を作る。
   - ユーザーの種類: 外部。アプリ名、サポートメール、プライバシーポリシー URL を入力。
   - スコープは `openid` / `email` / `profile` のみ(いずれも非機密スコープ)。
   - 公開ステータスを「本番」にする。この3スコープだけなら Google のアプリ確認は不要で、
     テストユーザーの人数制限も、リフレッシュトークンの7日失効もない。
2. **Android クライアント**を作る。パッケージ名と、署名証明書の SHA-1 を登録する。
   - Play 配布版: Play Console の「アプリの完全性」にある**アプリ署名鍵証明書**の SHA-1
     (Play App Signing で再署名されるため、ローカルの鍵の SHA-1 だけでは Play 版が動かない)。
   - 手元の debug / release ビルド: それぞれの鍵の SHA-1。
   - 同じパッケージ名 + SHA-1 は、全 Google Cloud プロジェクトで1つのクライアントにしか登録できない。
3. **ウェブアプリケーション クライアント**を作る。この **Web クライアント ID** が、
   - アプリの `serverClientId` になり、
   - バックエンドが ID トークンの `aud` として検証する値になる(秘密ではないが、シークレットはアプリにも Git にも入れない)。
4. ビルド時に Web クライアント ID を渡す。

   ```bash
   flutter build appbundle --release --flavor prod --dart-define=GOOGLE_SIGN_IN_CLIENT_ID=xxxx.apps.googleusercontent.com
   ```

   **flavor。** `prod` は `com.studio10dots.sharepi`(Play 配布版)、`dev` は
   `com.studio10dots.sharepi.dev`(アプリ名「SharePi Dev」)。パッケージ名が違うので実機に同時に入り、
   dev で試しても本番のデータは触れない。ビルド・実行には必ず `--flavor` を付ける。
   手順2の Android クライアントは、flavor ごとに作る(dev はデバッグ鍵の SHA-1 を
   `com.studio10dots.sharepi.dev` で登録、prod は Play 署名鍵の SHA-1)。Web クライアント ID は共通。

   ```bash
   flutter run -d <device> --flavor dev --dart-define=GOOGLE_SIGN_IN_CLIENT_ID=xxxx.apps.googleusercontent.com
   ```

5. リリース署名を設定する(現状のリリースビルドは debug 署名、`applicationId` は
   `com.studio10dots.sharepi`)。**`applicationId` は公開後に変更できない**。

## 2. メンバー(全員)

1. Play ストアからアプリをインストールする。
2. 初回起動で **Google アカウントでログイン**する。ここでアカウントが登録される。続けて**ニックネームの設定が必須**(スキップ不可)。後からプロフィール画面で変更できる。
3. 招待を受けたらグループに参加する(7章)。
4. 再インストールや機種変更でグループ一覧が消えたときは、「バックエンドURLから復元」でバックエンドのURLを入力する。
   参加済みのグループが戻る(再招待は不要。お気に入りは戻らない)。

ログインに使うアカウントは、プロフィール画面で変更できます。ただし変更すると、それまで見えていた
グループとイベントは見られなくなり、管理者からの再招待が必要です(画面に警告が出ます)。

---

## 3. オーナー: Google Cloud の契約

1. Google Cloud を契約し、**課金アカウント**を作る。
2. プロジェクトを作成し、課金アカウントを紐づける(バケットと Cloud Run の作成に必須)。

---

## 4. オーナー: Cloud Shell を開く

Cloud Console 右上の Cloud Shell を開く。`gcloud` と `terraform` が入っていて、自分のアカウントで認証済みです。
手元に何もインストールする必要はありません。

---

## 5. オーナー: バックエンドの作成

Cloud Shell で、リポジトリの Terraform を **コマンド1つ**で実行する。ファイルの編集は要らない
(公開者の値 `backend_image`・`google_client_id` は `terraform/backend/publisher.auto.tfvars` にあり、
Terraform が自動で読む)。アプリの「サーバー環境セットアップ手順」では、プロジェクトIDを入力すると
次の手順が現れ、IDと地域を埋め込んだこのコマンドが表示される。

- **プロジェクトID**: Cloud Shell が最初に向いているプロジェクトは、作成したものとは限らない。
  Terraform は gcloud の既定プロジェクトではなく、コマンドに渡された `project_id` を使う。
  作成したプロジェクトの **ID**(名前ではない。コンソールのプロジェクト選択に表示。英小文字・数字・ハイフンの6〜30文字)を
  `-var="project_id=..."` に入れる。形式が違えば Terraform が実行前に止める。
- **自分に近い地域を選ぶ**。下表の2文字コードを1つ選び、`region_for` に渡す(`region.sh` が
  GCP リージョン名に変換する)。

  | コード | 地域 | 使われるリージョン |
  | --- | --- | --- |
  | `ea` | 東アジア | asia-northeast1 (東京) |
  | `ca` | 中央アジア | asia-south1 (ムンバイ) |
  | `au` | オーストラリア | australia-southeast1 (シドニー) |
  | `me` | 中東 | me-central1 (ドーハ) |
  | `af` | アフリカ | africa-south1 (ヨハネスブルグ) |
  | `eu` | ヨーロッパ | europe-west1 (ベルギー) |
  | `na` | 北米 | us-central1 (アイオワ) |
  | `sa` | 南米 | southamerica-east1 (サンパウロ) |

```bash
git clone <リポジトリ URL> && \
cd sharepi/terraform/backend && \
source region.sh && \
terraform init && \
terraform apply -auto-approve \
  -var="project_id=<プロジェクトID>" \
  -var="region=$(region_for eu)"   # euの部分を選んだコードに置き換える
```

> **このコマンドを実行すると課金が始まります。** 確認の `yes` を省くため `-auto-approve` を付けてあり、
> 実行するとそのまま作成されます(アプリはコピー時にも同じ注意を出す)。
> 公開者が `publisher.auto.tfvars` を埋めていないと、実行前に止まる。

他の設定(`bucket_name`・`admin_emails`・`max_instances`・`log_retention_days`)を変えたいときだけ、
`terraform.tfvars.example` を `terraform.tfvars` にコピーして編集する(これも自動で読まれる)。

作られるもの: 必要な API、バケット(Autoclass・30日ソフトデリート・公開アクセス防止)、バックエンド用サービスアカウント
(鍵ファイルなし)、Cloud Run サービス、予算アラート(任意)。

- **管理者のメールは自動で入る**: `terraform apply` を実行したアカウントが管理者になる。
  別のアカウントにしたい場合は変数で上書きする。
- Terraform の状態(state)は、Cloud Shell のホームではなく、専用の小さな GCS バケットに置く
  (Cloud Shell のホームは永続ではない)。
- 完了すると、最後に **`backend_url`(Cloud Run の URL)** が表示される。これをアプリに入力する。
  あとから確認するときは `terraform output backend_url`。

## 5.5 オーナー: ブラウザ版を追加する(任意)

ブラウザで使いたい人だけの追加設定です。既定では作られません。PC でネットワークが安定している人向けで、
端末には何も保存しません(再読み込みで消えます。詳細は `Agents.md` 15章)。

```bash
terraform apply -var="enable_web=true" -var="web_image=ghcr.io/<公開者>/chamagon-web:1"
```

完了すると `web_url` が表示される。ブラウザでそこを開けば使える。バックエンドと同様、後から
`enable_web=false` に戻せば削除される。

---

## 6. アプリにバックエンドを登録する(オーナー)

1. アプリのプロフィール画面を開く。
2. バックエンドの URL を入力する。アプリが接続を確認し、自分が管理者であることを表示する。
   バックエンドの登録は1ユーザーにつき1つだけ。
3. グループを作成する(管理者のみ)。バケットは Terraform で作成済みなので、グループはその中のプレフィックスとして作られる。

---

## 7. 招待(オーナー → メンバー)

1. 管理者がグループの「招待」を開き、有効期限を **5 / 10 / 15 分**から選ぶ(既定 5 分)。
2. 画面に **QR コード**と**招待コード**(文字列)が出る。
   - 同じ場所にいる人: QR を読み取ってもらう。
   - 離れている人: 「コピー」で招待コードをクリップボードにコピーして送り、相手は「グループに参加」で貼り付ける。
3. 参加する人は Google アカウントでログイン済みの状態で、参加を確定する。参加画面にバックエンドのホスト名が出る。
4. 招待は**1回だけ**使える。期限切れや使用済みは、管理者が新しく発行する。
5. 招待画面を開いている間、管理者のアプリは数秒おきに参加状況を確認し、参加すると「○○さんが参加しました」と出す
   (プッシュ通知はない)。
6. 間違えて参加させた場合は、管理者がメンバー管理画面から退出させられる。

## 8. 運用

- **バックエンドの更新**: アプリは API のバージョンを確認し、範囲外なら更新を促す。
  バックエンドは現行と前2世代(3世代)をサポートする。メンバーがバックエンドを更新することはできないので、
  「バックエンドが古い」と出たらオーナーに伝える。オーナーは Cloud Shell で Terraform を再実行して更新する。
- **削除した写真**は、GCS のソフトデリートにより30日間は復元できる。
- **オーナーは運営者としての責任を負う**: 写真は、オーナー自身の Google Cloud に保存される。
  アプリの提供者は写真を受け取らず、見ることもできない。したがって、違法な内容(わいせつ物、
  児童ポルノ、本人の同意のない性的画像など)がバケットに置かれた場合の対応は、オーナーの責任になる。
  Google Cloud の利用規約に違反すると、プロジェクトが停止されることもある。
  - **報告を確認する**: メンバーの報告は、管理者の「報告」画面に届く。定期的に開いて確認する。
    理由には「露骨な性的画像・同意のない画像」と「未成年者(児童)に関わるもの」がある。
  - **見つけたらすぐ削除する**: 該当の投稿を削除し、投稿者をメンバー管理画面から退出させる。
    削除した写真は、ソフトデリートにより30日間バケットに残る。
    児童ポルノの疑いがあるものは、自分で見返したり保存したり転送したりせず、削除して、
    下記の窓口に通報する(所持・保管自体が違法になり得る)。
  - **通報先(日本)**: 警察(最寄りの警察署、またはサイバー犯罪相談窓口)、
    インターネット・ホットラインセンター(https://www.internethotline.jp/)。
    私事性的画像(リベンジポルノ)の被害相談は、警察のほか、違法・有害情報相談センターでも受け付けている。
  - **アクセスログ(IP アドレス)**: Cloud Run は、リクエストごとのログ(日時、URL、利用者の IP アドレス、User-Agent)を、
    Cloud Logging の `_Default` に自動で残す。標準の保存期間は30日。Terraform の `log_retention_days`(1〜3650)で変えられる。
    警察などからの照会に備えて延ばす場合は、費用と、利用規約に書いた保存期間との整合を確認する。
    写真の実体は、署名付き URL で端末から GCS に直接送られるため、Cloud Run のログには、その IP は残らない
    (残すには、GCS のデータアクセス監査ログの有効化が別に必要。標準ではオフ)。
  - **招待は信頼できる相手に**: 招待コードは使い捨てで短時間で失効するが、渡す相手はオーナーが選ぶ。
  - 提供者は、これらの内容をバックエンドの外から確認・削除できない。
- **費用の上限**: Cloud Run の最大インスタンス数を小さく設定し、予算アラートを設定する。
  外部に公開されるエンドポイントなので、大量アクセスを完全には防げず、課金の上限を抑えるための設定である。
- **コールドスタート**: アプリが前面に戻ったとき、最後の通信から約10分以上空いていれば、裏で `/ping` を送って起こす。
  バックグラウンドでは何も送らない。

## 10. よくある失敗

| 症状 | 原因 |
| --- | --- |
| Play 版だけログインできない(`DEVELOPER_ERROR` など) | Play のアプリ署名鍵の SHA-1 が Android クライアントに未登録 |
| 全員ログインできない | パッケージ名の不一致、または `GOOGLE_SIGN_IN_CLIENT_ID` に Android クライアント ID を渡している(Web クライアント ID が正) |
| バックエンドが 401 を返す | ID トークンの `aud` が、バックエンドに設定した `GOOGLE_CLIENT_ID` と違う |
| バックエンドを登録しても「管理者」と出ない | `ADMIN_EMAILS` と、アプリでログインしているアカウントが違う |
| 招待が使えない | 期限切れ、または使用済み。管理者が新しく発行する |
| 「バックエンドが古い」と出る | オーナーが Terraform を再実行して更新する必要がある |
| グループが見えなくなった | ログインアカウントを変更した。管理者の再招待が必要 |

## 11. 料金プラン(管理者)

グループごとに入れる人数(**管理者自身を含む**)は、管理者のプランで決まります。メンバーのプランは関係ありません。
共有中のグループ数にも、プランごとの上限があります。上限は世界共通で、価格だけ国ごとに違います。

| プラン | 購入方法 | 人数(グループごと) | 共有中のグループ数 |
| --- | --- | --- | --- |
| フリー | - | 7名まで | 20個まで |
| プロ | 買い切り | 15名まで | 30個まで |
| マックス | 買い切り | 20名まで | 40個まで |
| ビジネス | サブスクリプション(月額・年額) | 30名まで | 50個まで |
| ビジネス プロ | サブスクリプション(月額・年額) | 50名まで | 100個まで |
| ビジネス マックス | サブスクリプション(月額・年額) | 無制限 | 無制限 |

日本での価格は、プロ 200円、マックス 500円、ビジネス 月1,000円、ビジネス プロ 月2,000円、
ビジネス マックス 月5,000円です。年額は月額の10か月分です。実際の金額は購入画面(Google Play)に表示されます。

- 購入は Google Play を通して行い、状態は Google Play が保持する。端末の **Google Play アカウント**に紐づき、
  アプリのログインアカウントとは別に扱われる。再インストールや機種変更でも、同じ Play アカウントなら復元される。
- プランの確認は、アプリの起動時、前面に戻ったとき、前面にいる間の約1時間ごとに行う(バックグラウンドでは行わない)。
- 共有中のグループがプランの上限に達すると、新しいグループを作れない。人数の上限に達すると、新しい招待を発行できない
  (どちらもアップグレードの案内が出る)。
- **いまは Google Play に未登録のため**、デバッグ版では、プロフィール画面の「デバッグ用」欄で購入・オフライン・時間経過を
  試せる。リリース版はプランを確認できず、全員がフリーのままになる(共有が停止されることもない)。

**サブスクリプションが終了したとき**
1. Google Play がプランを確認できなくなると、最後に確認できた時刻から**3日間**は、共有を続けたまま、警告が出る。
2. **3日以上**経つと、残ったプランで持てないグループの共有が停止される。**人数が上限に収まり、しかも古い方から数えて
   グループ数の上限(フリーは10個)までのグループが残る。** それ以外のグループは、管理者以外のメンバーが「停止中」になる。
   停止したグループの数は、アラートで知らせる。
3. プランは、残っている購入に応じて、フリー(5名・10グループ)かプロ(10名)になる。

**停止したグループの扱いと復元**
- 停止中のグループでも、管理者は**メンバーを編集(退出)できる**。
- 停止中のグループは、管理者と停止中のメンバーの合計が、プランの人数の上限に収まり、しかも共有中のグループが
  グループ数の上限に満たなければ、**自動的にまとめて復旧**する(古いグループから)。メンバー側の操作も、再招待も要らない。
  部分的な復旧はしない。
- サブスクが戻ったときも、同じ規則で、収まるグループが復旧する(確認の問い合わせはない)。
- 停止中のグループには、招待を発行できない。

**注意**
- 上限の制御は管理者のアプリで行う。改造されたアプリやバックエンドでは回避できる。
- **1人の管理者は、1台の端末で使うことを推奨します。** 端末の Google Play アカウントを切り替えたり、
  別の Play アカウントの端末で同じ管理者として使ったりすると、契約が切れたように見えて、共有が停止されることがあります。
  その場合は、購入したアカウントに戻してください。停止されたグループは、収まれば自動で戻ります。
